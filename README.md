# Cloud Save Manager

Универсальный менеджер облачных сохранений для игр, у которых нет
собственной облачной синхронизации (Dark Souls III, Elden Ring и другие —
любая игра, если вы знаете, где лежит её файл сохранения).

Это переработанная версия старого проекта "DS3 Cloud Save Manager":
теперь приложение не привязано к одной игре и одному способу хранения.

## Оформление

По умолчанию — «жидкое стекло» (светлое). Другие оформления — «жидкое стекло» тёмное и прежние плоские светлое/тёмное — выбираются в Настройки → Общие → «Оформление» (применяется после перезапуска). Цвета и размеры — в `app/ui/tokens.py`.

## Что нового по сравнению со старой версией

- **Любые игры, а не только Dark Souls III.** Есть готовые пресеты
  (Dark Souls III, Elden Ring) и возможность добавить произвольную игру.
- **Ничего не нужно вводить вручную.** Не нужно знать имя процесса игры
  или путь к файлу сохранения:
  - кнопка **"Игра запущена — выбрать из списка"** показывает уже
    запущенные на компьютере программы — просто находите среди них свою
    игру (можно вводить часть названия для поиска);
  - кнопка **"Найти сохранение автоматически"** сама ищет вероятные
    файлы/папки сохранения в типовых местах (AppData, Documents, My
    Games, Saved Games и т.д.) — по совпадению названия и по недавно
    изменённым файлам — и предлагает выбрать из списка найденного.
- **Несколько бесплатных облачных хранилищ**, а не только GitHub:
  - GitHub (приватный репозиторий);
  - GitLab (приватный репозиторий, включая self-hosted инстансы);
  - WebDAV — подходит для **Яндекс.Диска** (10 ГБ бесплатно) и любых
    других сервисов с поддержкой WebDAV (Nextcloud, mail.ru и т.д.);
  - Локальная синхронизируемая папка — если на компьютере уже стоит
    Dropbox/Google Диск/OneDrive/Яндекс.Диск, можно указать папку внутри
    неё, и приложение вообще не будет использовать никаких токенов.
- **Автосохранение по таймеру убрано.** Слишком частые коммиты в
  GitHub/GitLab реально могут привести к ограничениям аккаунта. Вместо
  этого — отслеживание процесса игры:
  - при **закрытии** игры сохранение автоматически выгружается в облако
    (один раз за сессию, с небольшой задержкой);
  - при **запуске** игры приложение сверяет локальный файл с облаком и,
    если там есть более новая версия (например, вы играли на другом ПК)
    или обнаружен конфликт (менялось в двух местах), предупреждает и
    предлагает скачать — окно слота подсвечивается, приходит уведомление
    трея. Оба поведения можно отключить для конкретной игры.
- **Трей с быстрым сохранением.** Приложение можно свернуть в системный
  трей — оно продолжит следить за играми в фоне, не мешая работе. Пока
  игра запущена, в меню значка трея появляется её название с действиями
  **"⬆ Выгрузить"/"⬇ Загрузить"** прямо во время игры, без открытия окна.
  Если у игры несколько слотов (например, "Оригинал" и "Seamless
  Co-op") — у каждого своё подменю. **Если запущено сразу несколько
  игр — каждая будет отдельным пунктом меню**, ничего не перепутается.
  В настройках есть автозапуск вместе с системой (реестр на Windows,
  автозагрузка XDG на Linux), в том числе сразу свёрнутым в трей.
- **Один репозиторий — все игры, разложенные по папкам.** У облачного
  аккаунта GitHub/GitLab/WebDAV есть необязательное поле "Папка внутри
  репозитория" (например `Saves`). Один и тот же репозиторий можно
  использовать для всех игр сразу — каждая автоматически получает свою
  подпапку (`Saves/DarkSoulsIII/...`, `Saves/EldenRing/...`), ничего не
  перемешивается, создавать отдельный репозиторий под каждую игру не
  нужно. В окне добавления игры тут же показывается предпросмотр пути в
  облаке, чтобы всё было видно ещё до сохранения.
- **Собственный визуальный стиль.** Минималистичная чёрно-белая тема
  (своя иконка, карточки вместо плоских списков, отдельные цвета для
  "выгрузить"/"загрузить"/"удалить") вместо стандартного вида Qt-приложений.
- **Интерфейс на Qt (PyQt5)**, переработан под список из нескольких игр
  и нескольких облачных аккаунтов вместо жёстко зашитых под DS3 кнопок.
- Токены и пароли по возможности хранятся в системном хранилище паролей
  (`keyring`), а не в открытом файле — в "Настройках" видно, какой способ
  используется сейчас.
- **История резервных копий с восстановлением.** Кнопка "⟲" в карточке
  слота показывает все локальные резервные копии (дата, размер) с
  возможностью вернуть любую из них в один клик.
- **Пауза слежения одной кнопкой.** В боковой панели и в меню трея есть
  переключатель "⏸ Приостановить слежение" — временно выключает
  отслеживание всех игр разом, не трогая список игр и настройки.
- **Подтверждение для быстрой загрузки из трея** — по умолчанию выключено
  (скорость важнее, резервная копия создаётся всё равно), но можно включить
  в "Настройках", если хочется лишней подстраховки.
- Готовая иконка приложения (`assets/icon.ico`/`.png`) для сборки exe и для
  ярлыка автозапуска на Linux.
- **Поиск сохранений для "любой игры" стал умнее и запоминающим.** Как это
  устроено — честно:
  - для Dark Souls III и Elden Ring путь известен точно (готовый пресет —
    имя папки, имя файла, Steam App ID, проверено вручную);
  - для любой другой игры путь находится эвристически: поиск совпадений по
    названию папки + анализ недавно изменённых файлов. Теперь это окно
    поиска сузили до времени с момента запуска игры (а не "последние 4
    часа вслепую"), и из результатов убрали ложные срабатывания на саму
    папку установки игры (раньше она почти всегда "совпадала по названию"
    сама с собой, перебивая настоящее сохранение в AppData/Documents);
  - и главное: как только путь для какого-то процесса (.exe) подтверждён —
    через поиск или вручную — он **запоминается локально** (в привязке к
    типу папки, а не к конкретному диску/пользователю, так что переносимо
    между компьютерами). В следующий раз для игры с тем же .exe путь
    находится мгновенно и точно — программа по сути сама пополняет свою
    базу "пресетов" на основе вашего же использования, а не только двух
    встроенных.

## Быстрый старт

1. Установите Python 3.9+ и зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Запустите приложение:
   ```bash
   python main.py
   ```
3. Нажмите **"Облачные аккаунты..."** и добавьте хотя бы один аккаунт
   (см. ниже, какой выбрать).
4. Нажмите **"Добавить"** в списке игр — откроется окно с автоматической
   настройкой наверху:
   - запустите игру (если ещё не запущена), нажмите **"1. Игра запущена —
     выбрать из списка"** и найдите её среди запущенных программ;
   - сразу после этого запустится **"2. Найти сохранение автоматически"**
     — выберите нужный вариант из найденного списка (если сразу ничего
     не нашлось, запустите поиск повторно позже — например, сразу после
     первого запуска игры сохранения может ещё не быть);
   - при желании включите автовыгрузку при закрытии игры и проверку
     облака при запуске (включены по умолчанию);
   - выберите облачный аккаунт для этой игры и нажмите ОК.

   Готовые пресеты (Dark Souls III, Elden Ring) и ручной ввод пути
   остаются доступны ниже, если авто-поиск не сработал или вы предпочитаете
   настроить всё сами.
5. Играйте как обычно. При закрытии игры сохранение автоматически
   выгрузится в облако (если это не выключено в настройках игры). Также
   можно в любой момент нажать "Выгрузить"/"Загрузить" вручную.
6. Если хотите, чтобы программа тихо работала в фоне — в **"Настройки"**
   включите автозапуск вместе с системой и сворачивание в трей.
7. Пока игра запущена, сохранить её прогресс в облако можно прямо из
   трея: правой кнопкой по значку → название игры → "⬆ Выгрузить в
   облако". Работает и для нескольких одновременно запущенных игр.

## Автообновление из GitHub

Программа умеет сама проверять и устанавливать новые версии — отдельный сервер для этого не нужен:

1. В **Настройки → Обновления** включите проверку и укажите репозиторий в формате `owner/repo`.
2. Создайте релиз на GitHub, приложите к нему `CloudSaveManager.exe` и укажите тег версии (например `v1.1.0`).
3. При запуске программа тихо проверит релизы; если найдётся более новая версия — предложит скачать её и перезапуститься. Проверить вручную можно кнопкой «Проверить обновления сейчас» или через меню трея.

Автоматическая замена `.exe` работает в собранной Windows-версии. Если программа запущена из исходников (`python main.py`), она предложит страницу релиза — скачать архив придётся вручную.

## Какое облачное хранилище выбрать

Для GitHub, GitLab и WebDAV при добавлении аккаунта есть необязательное
поле **"Папка внутри репозитория"** — заполните его один раз (например
`Saves`), и этот же аккаунт можно будет использовать для всех
последующих игр: каждая получит свою подпапку автоматически.

| Вариант | Нужен токен/пароль | Плюсы |
|---|---|---|
| **Локальная синхронизируемая папка** | Нет | Проще всего, если уже установлен Dropbox/Google Диск/OneDrive/Яндекс.Диск |
| **WebDAV (Яндекс.Диск)** | Пароль приложения | 10 ГБ бесплатно, не нужен git |
| **GitHub** | Personal Access Token | Хранит историю версий сохранений (можно откатиться) |
| **GitLab** | Personal Access Token | То же самое, что GitHub, плюс можно поднять свой сервер |

### Локальная папка
Просто укажите путь к папке внутри уже установленного облачного клиента,
например `C:\Users\Имя\Dropbox\CloudSaveManager`. Токены не нужны.

### Яндекс.Диск (через WebDAV)
1. Откройте [id.yandex.ru → Безопасность → Пароли приложений](https://id.yandex.ru/security/app-passwords)
   и создайте пароль приложения типа **WebDAV** — обычный пароль от
   аккаунта не подойдёт.
2. В приложении выберите тип "WebDAV", адрес сервера
   `https://webdav.yandex.ru`, укажите логин и этот пароль приложения.

### GitHub / GitLab
1. Создайте **приватный** репозиторий.
2. Создайте Personal Access Token с правом на запись в репозиторий
   (GitHub: scope `repo`; GitLab: scope `api` или `write_repository`).
3. Укажите ссылку на репозиторий (или `namespace/project` для GitLab) и
   токен в диалоге добавления аккаунта — кнопка "Проверить подключение"
   покажет, всё ли верно.

## Сборка exe для Windows

В комплекте уже есть готовая иконка приложения (`assets/icon.ico`):

```bash
pip install pyinstaller
python -m PyInstaller --onefile --windowed --icon=assets/icon.ico --add-data "assets;assets" main.py
```

`--add-data "assets;assets"` кладёт иконку внутрь сборки, чтобы её мог
использовать, например, .desktop-файл автозапуска на Linux (для Windows
на это можно не обращать внимания — там иконка .exe берётся из `--icon`
напрямую). На Linux/macOS в `--add-data` используйте `:` вместо `;`:
`--add-data "assets:assets"`.

## Хранение данных и безопасность

- Список игр и облачных аккаунтов хранится в папке настроек приложения
  (`%APPDATA%\CloudSaveManager` на Windows, `~/.config/CloudSaveManager`
  на Linux/Mac) — не внутри папки проекта, поэтому эти данные не попадут
  в git, даже если вы сами сделаете из проекта репозиторий.
- Токены и пароли по возможности хранятся через `keyring` в системном
  защищённом хранилище. Если `keyring` недоступен (например, на сервере
  без графического окружения и без Secret Service), используется
  резервный локальный файл `secrets.json` в той же папке настроек — как
  и в старой версии программы.
- Локальные резервные копии перед перезаписью сохраняются в
  `<папка настроек>/backups/<игра>/<слот>/` (хранится 5 последних копий).

## FAQ

- **Файл сохранения не найден при автоопределении.** Запустите игру
  хотя бы один раз — папка с сохранением создаётся игрой при первом
  запуске/создании персонажа.
- **Ошибка доступа к GitHub/GitLab.** Проверьте токен и то, что
  репозиторий действительно существует и токену выдано право на запись.
- **Яндекс.Диск не принимает пароль.** Нужен именно "пароль приложения"
  типа WebDAV, а не обычный пароль от аккаунта.
- **Игра запущена через Steam Proton/Wine на Linux, а сохранение не
  находится.** Автоопределение проверяет стандартные пути compatdata —
  если у вас нестандартная установка, укажите путь к файлу сохранения
  вручную кнопкой "Изменить" у слота.
- **Не хочу автовыгрузку при закрытии игры.** Снимите галочку
  "Автоматически выгружать в облако после закрытия игры" в настройках
  игры — тогда останется только ручная выгрузка кнопкой.
- **"Обнаружен конфликт" при запуске игры.** Это значит, что сохранение
  менялось и локально, и в облаке независимо друг от друга (например,
  вы играли на двух компьютерах без выгрузки между сессиями). Программа
  не выбирает версию сама — при нажатии "Загрузить из облака" она
  предупредит об этом и создаст резервную копию локальной версии перед
  заменой, так что её всегда можно будет вернуть из
  `<папка настроек>/backups/`.
- **Автопоиск ничего не нашёл.** Не страшно — можно указать путь вручную
  кнопкой "Файл..."/"Папка..." в окне слота, либо немного поиграть и
  запустить поиск ещё раз (сохранение появится среди недавно изменённых
  файлов).
- **Как узнать, что программа работает в трее?** Значок появится в
  области уведомлений; двойной клик по нему открывает окно, через
  правую кнопку доступны "Настройки" и "Выход". Полный выход из
  программы происходит только через пункт "Выход" в трее — обычное
  закрытие окна сворачивает её (если это не отключено в настройках).

## Что исправлено в последней версии

- **Комфорт для новичка.** Один спокойный индикатор «Сохранения под контролем / в облаке есть новое / нужно выбрать версию» вместо набора технических статусов. При первом запуске предлагается «папка на диске без пароля» — не нужно разбираться с токенами. Инструкция переписана коротко и человеческим языком, подсказка значка в трее показывает, что происходит прямо сейчас.
- **Для геймера.** Кнопка с закладкой в карточке слота и в меню трея — «Быстрый
  снимок» в один клик прямо перед боссом, без диалогов и переключения из игры.
  Рядом с «Играть» — кнопка «Играть с облачной копии»: скачать сохранение с
  другого ПК и сразу запустить игру. В карточке видны размер сохранения и
  понятные даты последней синхронизации («сегодня, 14:30»).
- **Удобнее искать и ориентироваться.** Поиск по играм (название и имя процесса,
  Ctrl+F), подсказки на пустом экране с кнопками действия, относительные даты
  выгрузки («сегодня, 14:30») с полной датой в подсказке, горячие клавиши
  Ctrl+N / Ctrl+Shift+A / Ctrl+, / F2 / Delete.
- **Одно окно программы.** Повторный запуск (в том числе через автозапуск или
  ярлык) не открывает вторую копию: существующее окно разворачивается и получает
  фокус. Все диалоги — настройки, аккаунты, игра, сканер, прогресс выгрузки,
  подтверждения и файловый выбор — показываются **внутри главного окна**
  встроенными панелями с затемнённым фоном, а не отдельными окнами. Включено
  корректное масштабирование 125/150 % — интерфейс не «слипается».
- **Ничего не наезжает.** Кнопки карточек, статусы слотов, подписи в настройках
  и длинные пути в списках обрезаются многоточием с полным текстом в подсказке;
  длинные подписи чекбоксов переносятся. Все длинные формы (игра, аккаунт,
  настройки, сравнение версий, инструкция) прокручиваются, а минимальные размеры
  окон ограничиваются доступной областью экрана — ничего не вылезает за край
  даже при 150 % масштабе. Стеклянные поверхности стали плотнее, ползунки и
  рамки полей — контрастнее.
- **Ничего не перемешивается.** Результаты автовыгрузки сопоставляются по ID
  слота, а не по имени (одинаковые названия больше не путаются); путь в облаке
  очищается от `../` и не может попасть в папку другой игры; после долгой
  выгрузки не откатываются правки, сделанные в интерфейсе; две игры с одним
  .exe не перезаписывают запомненные пути друг друга.
- **Автовыгрузка после закрытия игры.** Игра считается закрытой только после двух
  опросов подряд без процесса (перезапуск лаунчера больше не даёт ложных срабатываний),
  имя процесса берётся и из `name`, и из имени `exe`, поддержаны усечённые имена Linux/Proton.
  При **запуске игры ничего не выгружается** — только сверка с облаком. Перед автовыгрузкой
  после закрытия облако проверяется ещё раз: если там версия новее или конфликт, выгрузка
  пропускается (приходит уведомление), чтобы не затереть более новое сохранение.
- **Архивирование и проценты.** Папки сохранений упаковываются в zip перед выгрузкой и
  распаковываются при загрузке (сначала во временную папку, потом заменяют локальную —
  битый архив ничего не испортит). Все операции показывают проценты и этап в одном окне
  вместо цепочки всплывающих сообщений.
- **Иконки.** Эмодзи заменены на SVG. У игр есть иконки: автоопределение (Steam-обложка по
  пресету/манифесту Steam/названию → иконка из .exe), либо своя картинка кнопкой
  «Выбрать с компьютера...». Иконки хранятся в `<папка настроек>/icons/`.


### Дополнительно исправлено
- Выход из трея теперь реально завершает программу и дожидается идущей выгрузки.
- Ручная выгрузка/выгрузка из трея спрашивает подтверждение, если в облаке версия новее.
- Резервные копии: порядок и обрезка по времени создания (раньше учитывалась дата исходного файла — могла удаляться свежая копия).
- Названия игр с `: ? * "` больше не ломают путь в локальной папке облака.
- Слот-папка, введённая вручную, определяется как папка и получает `.zip` в имени.
- Ссылки GitHub/GitLab (`.git`, `www.`, полный URL) разбираются корректно; запись в локальную папку — атомарная.
- Файл секретов создаётся сразу с правами 0600; mock-бэкенд keyring больше не считается защищённым.

## Дизайн: «жидкое стекло»
- Главное окно рисует живой фон: четыре цветные «капли света» медленно дрейфуют (`app/ui/glass.py`, `BackdropWidget`, ~30 кадров/с в активном окне, ~6 в неактивном). Когда окно свёрнуто в трей, таймер остановлен; при выключенных анимациях в настройках фон статичный.
- Карточки (`GlassFrame`) — полупрозрачная заливка из QSS плюс яркая кромка с градиентом и мягкий блик сверху. Кнопки и поля — матовое стекло с тонкой светлой кромкой, главная кнопка — градиент.
- Диалоги получают статичный градиент из цветов фона; меню и выпадающие списки непрозрачные (всплывающие окна Qt не умеют честно просвечивать).
- Плоские темы остаются: в них фон — обычная заливка, а `GlassFrame` ничего не дорисовывает.
- Стеклянные палитры лежат в `app/ui/tokens.py` (`glass`, `glass_dark`); полупрозрачные значения — в формате QSS `rgba(...)`, для рисования их разбирает `glass.parse_color`.

## Прежнее плоское оформление (Material 3, тёмная лесная тема)
- Все цвета, размеры, скругления, отступы и размеры шрифтов — в `app/ui/tokens.py`; стили собираются в `app/ui/theme.py`.
- Палитра: `#0B181F` фон, `#132523` поверхности, `#1F3F3A` карточки, `#4A6864` акцент, `#949DAA` вторичный текст.
- **Шрифт заголовков LPM PuffPuff (Shutters):** файл шрифта в репозитории не поставляется — положите `.ttf`/`.otf` в `assets/fonts/`. Если файла нет или в нём нет кириллицы, заголовок рисуется системным шрифтом (Segoe UI и др.).
- Иконки игр показываются только в заголовке выбранной игры (44–56 px, пропорции сохраняются); в списке слева — только названия.
- Статусы слотов (нет сохранения, облако новее, конфликт, облако недоступно, изменено после выгрузки) показываются тегами с иконкой и текстом и отражают реальное состояние.

### Дизайн
Минимализм: плоские поверхности без границ и градиентов, один акцент (шалфейная кнопка главного действия), статус слота — цветная точка и текст, путь по клику копируется. Токены — `app/ui/tokens.py`, стили — `app/ui/theme.py`. Шрифт заголовков LPM PuffPuff (Shutters) положите в `assets/fonts/`; без него (или без кириллицы в нём) используется системный шрифт.

## Надёжность (что добавлено)
- **Повтор автовыгрузки.** Если после закрытия игры выгрузка не удалась (нет сети, облако недоступно), программа повторит её через 30 с, 2 мин, 10 мин и 30 мин. Уведомление приходит о первой неудаче и об итоге.
- **Лёгкая проверка облака.** Рядом с сохранением в облаке лежит маленький файл `*.meta.json` (отпечаток, время, имя ПК). Проверка читает его, а не скачивает всё сохранение. Сохранения, выгруженные старой версией, проверяются по-старому (полным скачиванием) до первой новой выгрузки.
- **Сравнение версий.** При конфликте или когда облако новее открывается окно: время, размер и устройство для локальной и облачной версий; можно оставить любую.
- **Копия прежней облачной версии.** Перед перезаписью облака предыдущая облачная версия сохраняется в локальные резервные копии слота (файлы `backup_*_cloud*`, восстанавливаются так же, как обычные). Если облачный файл больше 100 МБ, копия не делается.
- **Журнал** — Настройки → «Открыть журнал».
- **Тесты:** `python -m pytest tests`. **Сборка .exe:** `build.bat` (PyInstaller, `CloudSaveManager.spec`).

## Дополнительные возможности
- **Шифрование (необязательно).** В окне аккаунта: «Шифровать сохранения перед выгрузкой (AES-256)» + пароль. Ключ получается из пароля (scrypt), пароль хранится в защищённом хранилище системы и в облако не попадает. **Потеряв пароль, облачные копии не открыть.** Файлы, выгруженные до включения шифрования, читаются как есть. Резервные копии прежних облачных версий хранятся расшифрованными. Имя ПК и отпечаток в `*.meta.json` не шифруются.
- **База путей сохранений (Ludusavi).** Раз в 30 дней (и кнопкой в настройках) скачивается открытая база путей сохранений игр; автопоиск сохранения сначала смотрит в неё, а Steam App ID оттуда используется для обложек. Индекс хранится в папке настроек (`save_paths_index.json`).
- **Dropbox.** Новый тип аккаунта: свой App key из Dropbox App Console и авторизация по коду (PKCE, секрет приложения не нужен). Проверено только на подставных HTTP-ответах — на реальном Dropbox испытайте кнопкой «Проверить подключение».
- **Выгрузка во время игры (необязательно).** В настройках игры: «Выгружать во время игры» — раз в N минут, только если файл не менялся последние 20 секунд и в облаке нет более новой версии. По умолчанию выключено.

## Второй компьютер: игры подхватываются сами
- Рядом с сохранениями в облаке лежит `_catalog.json` — список игр: название, процессы, слоты и **переносимые пути** (`{APPDATA}/…` вместо имени пользователя). При включённом шифровании аккаунта каталог шифруется тоже.
- На втором ПК достаточно добавить тот же аккаунт (то же хранилище и базовая папка): программа добавит недостающие игры, пересоберёт пути под этот ПК (если пути нет — поищет в базе Ludusavi) и, если локального сохранения нет, сама скачает его (перезаписывать нечего). Это же происходит при каждом запуске, а игры этого ПК публикуются в каталог.
- Удалённые вручную игры сами не возвращаются; вернуть: «Облачные аккаунты» → «Найти игры в облаке».
- Игры сопоставляются по имени папки в облаке (поле «Папка в облаке»), поэтому на разных ПК она должна совпадать — при автодобавлении так и будет.

## Тонкая настройка и оптимизация
- Настройки → «Слежение и выгрузка»: интервал проверки процессов, число проверок до «игра закрыта», пауза перед выгрузкой, «успокоение» файла, число резервных копий, повторы выгрузки; «Облако и данные»: каталог игр и автоскачивание.
- Контрольные суммы кэшируются по размеру и времени изменения (повторная проверка 60 МБ: ~125 мс → ~1.5 мс); опрос процессов не вызывает дорогой `exe()` без необходимости; сканирование папок через `scandir`; конфиги пишутся атомарно.

## Безопасность и удобство (последний проход)
- **Опасные пути.** Загрузка в папку слота отказывается заменять корень диска, домашнюю папку, AppData, Документы и т.п. Автоподстановка путей из облачного каталога разрешена только внутри профиля пользователя, общих папок данных и библиотеки Steam; иначе слот создаётся без пути и вы указываете его сами.
- **Кнопка «Играть».** Перед запуском программа сверяется с облаком: более новая облачная версия скачивается ДО старта игры, конфликт решаете вы. Команда запуска — в настройках игры (.exe или `steam://rungameid/ID`).
- **Маски «Не выгружать»** (для слотов-папок): `*.log, cache, screenshots/*`. Исключённые файлы не уходят в облако и не пропадают при загрузке.
- **Отмена** длинных операций в окне прогресса (до применения результата к локальным файлам).
- **Предыдущая облачная версия:** при каждой перезаписи облака старая версия остаётся рядом (`*.prev`); откат — в окне резервных копий слота («Откатиться к предыдущей облачной версии»).
- **CI:** `.github/workflows/ci.yml` (тесты на Windows и Linux, статическая проверка, сборка `.exe`); ручная проверка — `CHECKLIST.md`.

## Анимации и ресурсы
- **Анимации** короткие (120–220 мс) и одноразовые: плавное появление карточек при выборе игры, индикатора состояния при его смене, окон выгрузки/сравнения, плавный индикатор прогресса. Постоянных анимаций и таймеров нет; эффекты снимаются сразу после показа; при скрытом окне или выключенной опции («Настройки → Общие → Вид и ресурсы») ничего не анимируется.
- **Простой:** ~0 % процессора (измерено 12 с с открытым и скрытым окном), ~75 МБ памяти. Поток слежения спит до следующей проверки одним ожиданием, опрос процессов использует кэш имён (≈40× дешевле прежнего), строка статуса не обновляется при скрытом окне.
- **Экономия ресурсов после оптимизации:** живой фон рисуется в буфере половинного размера (в 4 раза меньше пикселей) и с 20 кадрами/с вместо 30; буфер переиспользуется между кадрами. В неактивном окне — 4 кадра/с. Обложки игр кэшируются по пути и времени изменения файла, поэтому перерисовка карточек не читает и не масштабирует картинки заново. Рабочая область пересоздаётся только при реальном изменении данных — повторные уведомления о синхронизации больше не заставляют Qt заново строить все карточки и пересчитывать стили.
- **Фон:** пониженный приоритет процесса; при скрытом окне — режим эффективности Windows (EcoQoS) и возврат памяти системе (на Windows не проверялось, на других ОС ничего не делается). Подготовка базы путей Ludusavi работает «на четверть мощности» (~20 % ядра, раз в месяц, ~2 минуты), стартует через 45 с после запуска и откладывается, пока идёт игра.

## Для игроков (последние функции)
- **Найти установленные игры** (лупа над списком игр): Steam (все библиотеки), Epic, GOG → пути сохранений по базе Ludusavi → одним нажатием добавляются процесс, запуск и слоты. Нужна скачанная база путей (Настройки → «Облако и данные»).
- **Снимки:** в окне резервных копий — «Сохранить снимок…» с подписью («перед боссом»); именные снимки живут, пока их не удалите. В настройках игры — автоснимки раз в N минут во время игры (хранятся последние 10; для слотов больше 300 МБ автоснимки не делаются, неизменённые папки не перечитываются). В списке копий видна разница размера с предыдущей; можно выделить несколько копий и удалить сразу.
- **Одна игра — один ПК:** при запуске игры в облаке ставится отметка «играют на …»; если игру запускают на втором ПК, программа предупредит (перед «Играть» и после запуска). Выключается в настройках.
- **Статистика:** время в игре и последний запуск — в шапке игры; «Продолжить: …» в меню трея; сортировка «недавние сверху» — в настройках.
- **Защита от битых файлов:** пустое локальное сохранение автоматически не выгружается.
